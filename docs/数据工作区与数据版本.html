数据工作区、数据版本与规则追溯

一个查询口径贯穿总览和明细

当前前端先解析具体snapshot_id，然后该轮指标、全表目录和行分页都携带这个ID。用户从高风险/正常/负责人统计下钻，明细带同样过滤条件。跨页或新数据到达不改变这次结果。切换快速连续触发时按请求代次检查，只有最后完整返回的一组summary/tables/rows进入画面。

左侧仅保留业务场景；目标、数据、Case、动作、执行、规则和证据入口在右侧固定工作区，与Hermes助手共用外壳，但仍以当前场景和快照为范围。

全表可查看，不等于一次加载所有行

dw_tables 登记各快照的原始表、处理阶段、映射/分类结果与Case投影；每张表保存字段并集，不因字段只出现在最后一行就丢列。行查询服务器游标分页，默认50，上限200；表格横向滚动显示全部已保存字段。内部 _source_refs 在追溯面板展示，不作为普通业务列刷屏。

版本目录默认30条一页，按日期/时间范围和 (data_at,seq) 游标定位。真实SQLite索引 dw_versions_date 负责历史分页；不创建每版本一套实体表，不OFFSET扫描几千页，不打开选择器就读取所有历史数据。

不可变快照保存什么

每次成功运行保留完整来源表、已声明阶段、最终结果、当时实际规则配置、参数、源时间与逐行引用。相同内容SHA256寻址并zlib压缩；dw_rows 引用 dw_blobs，减少重复原文和记录。原 runs 只保留快照引用，不再重复一份完整JSON。

WORKBENCH_DB 是全部业务表、快照、历史注释和会话的存储位置，.env.example 可指定持久化磁盘；默认 ./data/workbench.sqlite3。程序不自动删除历史数据，不把浏览器缓存当长期证据库。备份运行中的SQLite时应使用SQLite备份方式，或停服务再复制含WAL相关数据，不能只随手复制一部分文件。

状态栏持续显示实际数据快照时间与规则摘要。快照 data_at 是该次计算所代表的时点；各输入表的 source_times 单独记录其提供的业务时间和采集时间，不冒充所有上游同一时刻更新。来源缺少时间则保留未知。输入更新失败显示上一次成功快照＋失败提示，不显示零风险或伪“已刷新”。

最新模式跟随最新成功运行；历史模式固定不跳回，出现新数据只提示。快照URL、筛选和当前页面保留。历史复盘意见是现在追加的注释，不篡改当时记录。历史Case发起真实消息时先核对当前事实，不能以旧快照代替当前执行授权。

接入多表和保留中间表

POST /api/scenarios/<id>/data-bundle 的示意输入如下。该接口接入已取得的数据，不会未经配置扫描宿主机全部数据库。

{
  "main_table": "orders",
  "mode": "replace",
  "event_id": "batch-20260911-1530",
  "tables": [
    {"id":"orders","label":"订单底表","data_at":"2026-09-11T15:30:00+08:00","rows":[{"id":"A","name":"示例订单"}]},
    {"id":"supplier","label":"供应商底表","data_at":"2026-09-11T14:00:00+08:00","rows":[{"id":"S1","name":"示例供应商"}]}
  ]
}

业务配置 pipeline 显式声明每步id、kind（identity/sql/python）、input、source。SQL可查询登记的输入表；Python使用 transform(rows, parameters, tables)，返回列表或 {"rows": [...], "tables": {"中间表名": [...]}}。

需要证明多表逐行关联时返回 _source_refs: [{"table":"orders","key":"A"},{"table":"supplier","key":"S1"}]。追溯沿已记录的引用逐级读取源行、步骤和规则命中，检测缺行/循环并限制单次展开深度和数量；不会依靠相同id推断任意Python/SQL只使用了某一条原数据。

**未登记的数据源、未输出的Python临时变量、已丢弃的中间表不能事后凭空恢复。**画面明确提示table-level-only等缺失。旧版快照转换只展示当时真保存的内容，不伪造中间表。

原文规则与实际执行一致

规则页直接展示所选快照的source/触发/参数/pipeline或processor完整代码、字段映射、按顺序计算的derived、首个命中的分类rules、rule_sources原文和rule_coverage映射。长SQL/Python/原文可展开，不用进入“编辑”才知道如何计算。

rule_sources 和 rule_coverage 需包含实际提供的文件、章节、原文和实施映射。它们是可核验依据，不是系统自动证明所有正式规则语义已经正确。当前只有随包样例，没有用户完整正式规则文档，因此不能声明已验证未提供的那套业务规则。

Hermes行级解析与Case快捷操作

查看行 → 展示实际形成链路 → “请Hermes解析”或催办/指派/认领快捷入口 → 将当前快照、表、行、证据和意图填到右侧输入框。快捷点击不创建模型执行、更不直接发送邮件。用户提交后走原Hermes API/WebUI、工具批准和Skill回执逻辑。

解析不是把全部数据源每次塞给模型；传当前行可核验链路及当时参数，必要时继续查指定表。没有引用的地方必须说明未知。历史操作标明当前状态需要核对；消息提交、送达、Case闭环分别处理。

供应链 Agent 工作台 2.2.0-rag；实际运行与未验证范围分别记录。
