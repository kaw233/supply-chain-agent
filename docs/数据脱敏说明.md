# 演示数据与脱敏说明

## 结论

公开仓库不包含企业内部数据源、生产数据库、真实飞书产物或真实 RAG 文档。`examples/` 与 `packs/` 中的物料、交期、质量记录均为全合成演示数据，用于展示规则、Case、追溯与 Agent 动作合同。

早期样例虽然同样是程序生成数据，但使用了拟真的中文人名、城市工厂名、供应商名和业务编号，容易被误认为真实主体。当前版本已进一步做不可关联化处理。

## 当前约定

| 数据类型 | 公开样例约定 |
| --- | --- |
| 人员 | `示例负责人A` 等角色编号，不使用自然人姓名 |
| 邮箱 | `owner-a@example.invalid` 等保留域名，不可真实投递 |
| 工厂 | `示例工厂A` 等抽象地点，不包含城市或地址 |
| 供应商 | `合成供应商A` 等虚构主体，不映射真实企业 |
| 物料、订单、批次 | `DEMO-MAT-*`、`DEMO-SO-*`、`DEMO-LOT-*` |
| 制造订单 | `DEMO-MO-*` |
| 数量与金额 | 为规则覆盖而生成的离散演示值，不来自业务统计 |

产品类别名称属于通用工业词汇，仅用于说明场景，不表示任何企业产品目录。示例中的规则阈值也只是演示口径，不代表实际企业制度。

## 未进入仓库的内容

- `data/`：本地 SQLite、DSH Profile、飞书接收产物及运行状态。
- `reports/`：本地测试与验证报告。
- `.env`：本地环境配置和可能的连接信息。
- 真实模型密钥、飞书身份、ERP 账号、企业文档和 RAG 索引。

这些路径由 `.gitignore` 排除。对外部 DSH、MCP、飞书 CLI 和 RAG Provider 的描述均为接口合同，不包含真实租户、群组、员工或文档标识。

## 自动审计

运行：

```bash
python scripts/data_privacy_audit.py
```

审计会验证：

1. `examples/` 与 `packs/` 内容一致；
2. 所有演示记录都明确使用 `DEMO-*` 标识；
3. 人员、工厂和供应商采用不可关联占位值；
4. 邮箱只使用 IANA 保留的 `.invalid` 顶级域；
5. 场景说明明确声明数据为全合成与虚构。

该检查已加入 GitHub CI。它用于防止常见回归，但不能替代组织的数据分类、人工复核和 Git 历史 Secret Scanner。
