# 缺料催交基础场景

这是社区版的第一条可运行业务闭环：

`SQLite 业务数据 -> 确定性缺口规则 -> Case -> 催交草稿 -> 人工确认 -> DSH/Hermes -> MCP Mock ERP -> 回执与审计`

## 边界

- 缺口和风险等级由确定性规则计算，不由大模型猜测。
- 本地 DSH SDK（或兼容 Hermes）负责会话、调用已登记的 MCP/CLI 工具和回传结果。
- 本轮只实现供应商催交；调拨、替代料、Celery、LangGraph 和预测模型不在这个最小版本内。RAG 仅提供接口与审计框架，未接入数据源、Embedding 或向量检索。
- Mock ERP 是可重复验证的脱敏接口替身，不代表已连接真实 ERP/MES。

## 启动

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\start-mock-erp-mcp.bat
```

FastMCP 默认提供 `http://127.0.0.1:8000/mcp` Streamable HTTP 端点。在实际 DSH/Hermes 工具配置中将该端点登记为 `supply-chain-mock-erp`，再启动工作台。登记提示和工具白名单见 `dsh_runtime/integrations.example.json`；它是 provider-neutral 模板，不会冒充 DSH 已自动注册。仅启动 SDK 不代表 MCP 已登记：

```powershell
.\start.bat
```

在“物料齐套协同”中选择一条高风险 Case，调用“供应商催交”能力生成草稿。草稿中的 payload 是不可猜测的执行参数，包含业务对象版本。

## MCP 工具

- `prepare_expedite`：校验参数并持久化待提交操作。
- `commit_expedite`：重新校验对象版本后提交，重复请求返回同一外部编号。
- `rollback_expedite`：取消尚未提交的准备记录。
- `get_operation_status`：按操作编号或幂等键查询持久状态。

MCP 服务默认仅用于本机开发和集成测试。服务间 JWT、主管 RBAC 和真实 ERP 适配器是后续工作，本版不宣称已完成。

## 定时飞书输入

飞书图片由外部 DSH 定时任务和已安装的飞书 CLI Skill 拉取，工作台只接收清单和可选的已标准化业务记录，不在对话中实时生成图片或调用飞书开放平台。定时任务调用：

```text
POST /api/integrations/feishu/{scenario_id}/batches
```

请求合同为 `scheduled-feishu-cli-v1`。`event_id` 是幂等键；`artifacts` 只保存附件编号、类型、摘要和工作区内相对路径。不要把 access token、Cookie 或 Authorization 写入 `uri`、metadata 或日志。若同时提交 `records`，工作台会按现有确定性规则运行一次并保存数据版本；同一 `event_id` 重试会返回原批次，不会重复计算。读取清单使用：

```text
GET /api/integrations/feishu/{scenario_id}/artifacts?limit=50
```

该社区包的 HTTP API 沿用本地工作台的信任边界，没有额外的飞书 webhook 签名校验。生产部署必须让调度任务与工作台处于受控网络，或在反向代理增加 mTLS/HMAC/服务账号鉴权后再暴露该入口；不能把此示例端点直接公开到互联网。
